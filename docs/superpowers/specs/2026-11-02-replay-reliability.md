# Capture reliability, bounded replay, dynamic app audio and public updates

User-approved scope: implement points1–4 from the gap review; public GitHub; no fixed application-audio count; only apps audible within a saved clip get a stem; use locally installed Medal clip cue without redistributing its asset.

Architecture decisions: retain libobs/NVENC capture and waveform quality. Replace stock RAM-only replay with keyframe-owned packet journal, disk or RAM selected honestly, snapshots pinned during saves, explicit limits/free-space protection. Unbounded process audio runs independently of OBS's six mixer buses: enumerate Windows audio sessions, capture each app process tree through Windows process loopback, keep time-stamped sparse PCM chunks, select and align only non-silent apps overlapping actual video snapshot window, encode AAC only at finalization. Keep original replay/sidecars until verified atomic output. Existing combined audio and mic remain compatible; editor already discovers MP4 streams dynamically. No pixel-sameness freeze alarm: transport freshness plus window/hook lifecycle, bounded retries and WGC fallback, preserving game-only policy and Quake shared-memory workaround. Public updates use anonymous HTTPS GitHub API and retain signature/hash/size/rollback checks. Medal asset stays in user data, custom import selectable locally.

Safety: never touch game settings or close games; stage tests separately from live app; preserve live buffer before restart. No arbitrary fixed audio app cap; OS resource failures explicit, never silent missing tracks. No friend-ready setup/Release unless separately requested. Repository audit precedes public visibility; no secrets/profile/media in history. Existing audio calibration applied to sidecar timestamps before alignment.
